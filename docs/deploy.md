# Публикация сайта — безопасная система

GitHub — единственный источник правды. Сервер тянет объединённую версию
из `main`, а не чью-то локальную копию. Поэтому работа из нескольких
сессий/агентов не затирает друг друга: git при пуше заставляет слить
изменения, а сервер публикует уже слитый результат.

## Как публиковать (из корня проекта)

1. Внести правки в `public/`.
2. Отправить в GitHub:
   ```
   git add -A && git commit -m "..." && git push origin main
   ```
   Если кто-то уже пушил — git попросит сначала слить (`git pull --rebase`),
   ничего не теряется.
3. Посмотреть, что изменится на бою:
   ```
   bash preview-deploy.sh
   ```
4. Опубликовать:
   ```
   bash deploy-to-server.sh
   ```

## Что делает публикация
- Сервер (`/opt/terranova`) тянет свежий `main` из GitHub.
- Делает бэкап текущего сайта в `/var/backups/terranova/` (хранятся 10 последних).
- Синхронизирует `public/` в веб-корень `/var/www/terranova/`.

## Откат
Восстановить прошлую версию из бэкапа:
```
ssh ... 'cd /var/www/terranova && tar xzf /var/backups/terranova/web-ДАТА.tar.gz'
```

## Правило при работе из нескольких сессий
Публикует всегда `main`. Перед `deploy-to-server.sh` обязательно `git push`.
Стало нельзя случайно залить стухшую локальную копию — сервер берёт только GitHub.
